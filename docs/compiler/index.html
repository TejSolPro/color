01 / What it returns

Eleven roles.
Every one explained.

Foundation

Canvas, surface, default text, and readable muted text.

Action

Locked primary, on-primary label, hover state, subtle surface, and a visible boundary.

Access

Meaningful neutral border and keyboard focus ring, both tested against the canvas.

Evidence

Exact pairs, criteria, required ratios, measured ratios, decisions, and provenance.

02 / The promise

The input stays locked.

Preserve

The supplied brand and canvas are normalized, never silently replaced or “improved.”

Derive

Supporting colors use documented deterministic transformations instead of model improvisation.

Audit

Text, hover, boundaries, and focus are tested as the exact pairs people will see.

Inspect

Schema version, algorithm version, and token-level provenance travel with the result.

03 / For agents and code

Structured in.
Structured out.

Agents do not need to interpret a screenshot or scrape design advice. They can call the core function or CLI and receive stable semantic names with evidence.

import {
  compileOneBrandTheme,
  exportThemeCss,
} from "@tejsolpro/color";

const theme = compileOneBrandTheme({
  brand: "#9d3f2d",
  canvas: "#f3efe7",
});

theme.tokens.primary;       // "#9d3f2d" — unchanged
theme.allRequiredPairsPass; // true
exportThemeCss(theme);      // :root { ... }
solpro-color theme "#9d3f2d" --canvas "#f3efe7"
solpro-color theme "#9d3f2d" --format css

The packages are currently consumed from the repository and are not yet published to a package registry. The browser playground is ready to use now.

04 / Honest boundaries

Focused by design.

Version 0.1.0 does not interpret a creative brief, select historical palettes, generate dark mode, or export framework-specific configurations. It solves one narrower problem completely: extend a locked brand color into a traceable first interface system.

Those larger capabilities remain on the public roadmap and will reuse this contract rather than replacing it with vendor-specific logic.
